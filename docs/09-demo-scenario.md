# 09. 시연 시나리오

발표 때 화면에서 무엇을 어떤 순서로 보여 줄지 정한 대본이다. 데이터는 [08 데모 데이터](08-demo-data.md)의 P1~P5 현재 버전을 쓰고, 장면에 나오는 숫자는 모두 생성 코드가 계산한 값(`truth.json`의 `facts`)이다.

- **가정**: 메인 시연 10분 + 질문·시간에 따라 예비 시나리오. 시연 시간과 청중은 아직 정해지지 않았다.
- **상태**: 목표 대본이다. 웹 UI, `agent.run`, 계산 함수가 아직 없어서 지금은 그대로 시연할 수 없다. 장면별로 필요한 기능과 현재 상태는 [§5](#5-시연에-필요한-기능과-현재-상태)에 있다.
- 에이전트의 실제 문장은 에이전트가 만든다. 아래 "예상 답변"은 흐름을 맞추기 위한 예시이고, 채점 기준은 각 페르소나의 평가 케이스(`expect` / `must_not`)다.
- 시연은 운영 첫 2주(12/1 ~ 12/14)만 쓴다. 데이터는 LLM 평가용으로 1/31까지 늘었지만 이 2주는 처음 만든 그대로다 (테스트로 고정). 시간이 남으면 12/20 이후 장면(P4 종강총회·부모님 추가 송금 등, [08 §3](08-demo-data.md#3-페르소나-5명))을 예비로 쓸 수 있다.

## 1. 보여 줄 것 (청중에게 남길 메시지)
1. **3개월 내역 + 몇 가지 질문으로 그 사람의 소비 쟁점을 찾는다.** 원인을 하나로 단정하지 않는다.
2. **숫자는 계산 코드가 만든다.** 답변의 숫자마다 계산식이 붙고, 검증기가 확인한다.
3. **검색 결과는 별도 창에만 뜬다.** 계산에는 사용자가 판매처에서 확인해 입력한 가격만 쓴다.
4. **결정은 사용자가 한다.** 에이전트는 선택지를 0~3개 내고, 개입할 가치가 없으면 조용히 있는다.
5. **기록할 때마다 잔소리하지 않는다.** 유저가 기록을 남기면 조용히 이해만 하고, 일요일 저녁 주간 피드백과 말일 저녁 월간 피드백에서 정리해 말한다 ([10 §2](10-llm-eval-plan.md)).

## 2. 준비
| 언제 | 할 일 |
|---|---|
| 전날 | `uv run python -m spending_agent.demo build P4`, `build P1` (온보딩분만). 리허설 1회, 시간 재기 |
| 전날 | 장면별 화면 녹화(예비용). 실시간 시연이 안 될 때 바로 틀 수 있게 |
| 시작 전 | 세션 초기화 (P4·P1 대화 기록 지우기), 화면 배율, 알림 끄기 |
| 시작 전 | 검색 창은 제공자가 미정이라 가짜 검색 창(`fake_search_panel`)으로 띄운다는 것을 발표 때 밝힌다 |

화면 구성: 왼쪽 채팅, 오른쪽 검색 창 카드(답변과 분리), 위쪽 날짜 표시와 "하루 넘기기" 버튼, 아래쪽 기록 입력란.

## 3. 메인 시연: P4 (24세 대학생, 자취·카페 알바·동아리 총무) — 약 8분
P4를 고른 이유: 지출보다 **수입 감소**가 원인이라 "줄이세요"만 하면 틀리는 사례다. 더치페이·이름 없는 이체·앱 오분류 같은 함정도 있다.

### 3-1. 온보딩: 기초 고정 질의 (40초)
| 화면에서 할 것 | 기대 동작 | 말할 것 |
|---|---|---|
| 고정 질의에 답한다. 지금 모아 둔 돈 "80만 원", 수입 "부모님 용돈이랑 카페 알바요", 거주 "자취, 원룸 월세", 줄이기 싫은 것 "동아리 활동" | 답변이 프로필에 저장된다. **목표는 여기서 묻지 않는다** (내역을 보여 준 뒤 대화로 정한다, 3-4) | "처음엔 생활과 줄이기 싫은 것만 묻습니다. 목표는 지금 쓰는 돈을 보고 같이 정합니다." |

### 3-2. 온보딩: 거래내역 불러오기 (30초)
| 화면에서 할 것 | 기대 동작 | 말할 것 |
|---|---|---|
| 자산관리 앱에서 내보낸 CSV(`data/demo/P4/onboarding/transactions.csv`, 9~11월 219건)를 올린다 | 월별 지출 요약, 정기 결제, 이름 없는 입금·출금 목록이 보인다 | "은행·카드·간편결제가 이미 합쳐진 통합 내역을 올린다고 가정합니다." |

### 3-3. 온보딩: 패턴 파악 → 추가 질의 (1분 30초)
에이전트가 내역에서 이상한 점을 찾고, **확인이 꼭 필요한 것만** 묻는다. 온보딩 질문은 목표 대화(3-4)까지 합쳐 5개로 제한한다 (`harness.MAX_QUESTIONS_ONBOARDING = 5`, 주간·월간은 3개).

| 에이전트 질문 (예상) | 데이터 근거 | 시연자 답 (숨은 사실) |
|---|---|---|
| "금요일 저녁 큰 결제 뒤에 소액 입금이 여러 건 들어오는데, 대신 내고 정산받으시는 건가요?" | 큰 결제 뒤 3일 안에 같은 금액 입금 (truth `dutch_groups`) | H1 "제가 동아리 총무라 먼저 내고 애들이 보내줘요. 가끔 안 주는 애도 있고요." |
| "10일 입금이 9월 609,210원에서 11월 406,140원으로 줄었어요. 알바 시간이 줄었나요?" | 10일 입금 감소 (`monthly.income.알바`) | H2 "가게가 평일 오후 타임을 없애서 알바를 덜 하게 됐어요." |
| "매달 11일 10만 원 출금이 11월에는 없어요. 어떤 돈인가요?" | 정기 출금이 11월에 끊김 | H3 "노트북 적금이요. 11월엔 돈이 없어서 못 넣었어요." |

- 1일 입금(용돈)과 25일 출금(월세)은 고정 답변으로 추정할 수 있으니 묻지 않고 확인만 한다 (케이스 P4-C05).
- 점심의 '한누리대학교생활협동조합'이 앱에서 쇼핑으로 분류된 것(P4-C07)은 질문 한도(목표 대화 2개를 남겨 둔 3개)에 들지 않으면 다음 기회로 미룬다. 질문 한도 때문에 에이전트가 우선순위를 고르는 장면이다.

### 3-4. 온보딩: 목표 대화 → 보고서 → 목표 생성 (1분 30초)
에이전트가 지금 쓰는 돈과 남는 돈을 먼저 보여 주고, 목표를 묻는다. 숫자는 모두 계산 결과다.

| 에이전트 (예상) | 숫자 (계산 결과) | 시연자 답 (숨은 사실) |
|---|---|---|
| "9~11월에 달마다 남은 돈(수입 − 지출)은 9월 142,410원에서 11월 51,340원으로 줄었어요. 무엇을 위해, 언제까지 얼마를 모으고 싶으세요?" | 월세 이체는 지출, 정산 입금은 수입이 아님. 평균 86,483원 | G1 "졸업작품 하려면 노트북이 있어야 해요. 2월 말까지 130만 원 모으고 싶어요." |
| "그러면 매달 166,667원이 필요해서 지금보다 80,184원을 더 남겨야 해요. 시점이나 금액을 바꿀 여지가 있을까요?" | (1,300,000 − 800,000) ÷ 3개월 = 166,667원, 166,667 − 86,483 = 80,184원 | H8 "개강하고 3월 중순까지만 있으면 돼요. 중고도 괜찮고요." |
| 보고서(카테고리별 월평균 소비, 소비 패턴, 달마다 남는 돈, 줄여야 할 금액)와 목표안을 보여 준다. 예: "중고 120만 원, 2027-03-15까지" | (1,200,000 − 800,000) ÷ 4개월 = 100,000원, 100,000 − 86,483 = 13,517원을 회식비 미리 걷기·배달 조정으로 | 시연자가 목표안을 확인하고 (필요하면 고친 뒤) **목표 생성** 버튼을 누른다 → 온보딩 끝 |

- 유저는 목표안을 고칠 수 있다. 하네스에서는 유저가 받아들일 수 있는 범위(시점 3/15까지, 금액은 낮춰도 됨) 밖인 칸만 고친다 (`Simulator.create_goal`).
- 만든 목표는 주간·월간 피드백의 기준이 된다 (목표 달성도 도구 `goal_progress`).

### 3-5. 온보딩: 보고서의 쟁점 (1분)
3-4의 보고서에 함께 나온다 (목표 생성 버튼을 누르기 전에 본다).

| 기대 동작 | 숫자 (계산 결과) | 하면 안 되는 것 |
|---|---|---|
| 원인을 하나로 말하지 않는다. 가장 큰 원인은 수입 감소이고, 지출 쪽은 하나하나가 작다고 짚는다 | 원하는 목표의 필요 월 166,667원 / 수입 감소 월 203,070원 / 배달 46,533원 · 편의점 39,633원 · 못 받은 정산 9,400원 (3개월 평균) | "외식비가 많다", "동아리를 줄이세요" (P4-C03, C16) |
| 선택지 0~3개를 크기 순으로 낸다. 예: ① 목표 시점·방식 조정 (3-4의 목표안) ② 회식비를 미리 걷는 방식 ③ 배달 줄이기 | 각 선택지의 영향은 계산 함수 결과로만 | 선택지 4개 이상, 지출 절감만 제안 (P4-C14) |

말할 것: "대부분의 가계부 앱은 '식비가 늘었다'고 말할 겁니다. 실제로 내역만 합치면 9월 218,200원에서 10월 380,200원으로 늘어 보입니다. 하지만 그건 동아리 대표 결제 총액이고, 진짜 원인은 알바비입니다."

### 3-6. 운영: 기록은 조용히 이해하고, 일요일 저녁에 정리해서 말한다 (3분)
"하루 넘기기" 버튼으로 날짜를 옮긴다. 거래는 매일 쌓인다. 유저가 거래를 골라 기록을 남기면 **유저 이해만** 돌고 에이전트는 말하지 않는다. 시연 화면에서는 "이해한 내용" 패널로 보여 준다. 쟁점 업데이트와 제안은 주간(일요일 저녁)·월간(말일 저녁) 피드백에서만 나온다.

| 날짜 | 화면에서 할 것 | 기대 동작 | 보여 줄 포인트 |
|---|---|---|---|
| 12/2 (수) | 기록 R1 "휴지랑 세제 떨어져서 또 샀다. 매번 작은 것만 사는 것 같음" (12/1 '알뜰마트연희' 8,900원에 연결) | 유저 이해: "생필품을 소량으로 자주 산다"를 메모하고, 다음 피드백 때 물을 질문(보관 공간)을 모아 둔다. 말하지 않는다 | 기록할 때마다 잔소리하지 않는다 |

| 12/11 (금) | 기록 R4 "알바비 들어왔는데 생각보다 너무 적다. 이번 달도 적금 못 넣을 듯" (12/10 입금 243,690원에 연결) | 유저 이해: 수입 감소가 계속된다고 메모한다. 말하지 않는다 | |

## 4. 짧은 사례: P1 (27세 직장인, 오피스텔 월세) — 약 1분 30초
쉬운 사례로 "빨리 끝나는 것은 빨리 끝난다"를 보여 준다.

| 장면 | 기대 동작 | 숫자 (계산 결과) |
|---|---|---|
| 온보딩 요약 | OTT 2개(무비온, 씨네박스), 음악 2개(소리랑, 멜로디플러스는 10월부터) 중복과 씨네박스 가격 인상을 바로 보여 준다. 무엇을 실제로 쓰는지와 목표(G1: 4월 말 일본 여행 210만 원)를 묻는다 | 씨네박스 9,900 → 12,900원 / 필요 월 260,000원 |

## 6. 안 될 때 (플랜 B)
- 장면별 녹화 영상을 바로 튼다. 녹화는 기능이 붙는 대로 리허설 때 만든다.
- LLM이 없거나 불안정하면 가짜 LLM에 장면별 정해진 응답을 넣어 진행한다. 그래도 숫자는 계산 함수 결과를 쓰고, 정해진 응답이라는 것을 밝힌다.
- 검색 창이 안 뜨면 가격 입력 폼만으로 계산 장면을 보여 준다.
