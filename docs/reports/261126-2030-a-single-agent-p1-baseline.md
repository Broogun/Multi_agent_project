## 결론
| 항목 | 값 |
|---|---|
| 구성 | 단일 에이전트 (gpt-6.1-terra + Python 계산 Tool) |

| 1회 실행 비용 | 입력 356,495 · 출력 3,514 토큰 · 134초 |

**잘한 것**: 보호 구독(씨네박스) 유지, 카드대금 이중 집계 회피, 결정은 사용자에게 맡김, 가격 인상 알림

**단일 에이전트의 약점 4가지**
1. **복합 결론을 못 낸다.** 구독 정리, 배달 조정, 저축 부족분을 한 결론으로 묶지 못했다 (C08).
2. **새로 생긴 걸 알아채지 못한다.** 첫 결제나 새 구독을 "새로 시작됐다"로 잡지 못했다 (C05).
3. **질문 3개 중 2개를 이미 거의 알 수 있는 데 썼다.** 월세·적금처럼 정형적인 이체를 물었다.
4. **입력 토큰이 대화가 길어질수록 계속 커진다.** 운영이 길어지면 비용과 속도가 같이 나빠진다.

> P1 한 번, 한 모델 결과다. 반복 실행과 다른 페르소나는 아직이다. 채점 오판 1건(C06)이 있어 점수는 참고용이다.

## 약점의 원인
맥락을 잊어서 생긴 문제는 아니다. 멀티턴으로 돌렸고 전체 대화를 유지했다. R1에서 "씨네박스 유지"를 기억했고, R4에서 지난달 대금과 비교했다.

| 약점 | 필요한 정보가 있었나 | 원인 |
|---|---|---|
| 1. 복합 결론 (C08) | 있었음. 필요 240,000 · 적금 200,000 · 배달 242,400을 온보딩에서 계산 | 숫자를 묶어 결론을 내지 못함. 3만 토큰 넘게 쌓인 맥락 속에서 앞 숫자를 다시 못 꺼냈을 가능성도 있음 (미검증) |
| 2. 새 결제 감지 (C05) | 있었음. "이전 내역에는 없어서"라고 말함 | 관찰을 "새로 시작된 구독"이라는 판단으로 잇지 못함 |
| 3. 질문 우선순위 | 온보딩 한 턴 안의 일 | 무엇을 물을지 고르지 못함 (기억과 무관) |
| 4. 토큰 증가 | – | 기억을 유지하는 방식(전체 재전송)의 비용 |

## 멀티 에이전트로 나눌 근거
| 약점 | 3분할 구조에서의 대응 |
|---|---|
| 1. 복합 결론 | 전략 담당 + 자기 비평(Critic). 부족분 · 지렛대 크기를 요약 상태(칠판)로 넘겨 앞 숫자가 묻히지 않게 한다 |
| 2. 새 결제 감지 | 새 결제 · 가격 변경은 규칙 코드(반복결제 비교)로 먼저 잡아 칠판에 올린다 |
| 3. 질문 우선순위 | 정형 이체는 규칙으로 처리하고, 질문 한도는 숨은 사실 확인에 쓰도록 유저 이해 담당이 고른다 |
| 4. 토큰 증가 | 대화 전체 대신 칠판(요약 상태)만 넘긴다. 이번 수치가 비교 기준선 |
| 암산 | 숫자 검증기(`verify_response`)를 하네스에서 강제한다 |

## 고친 것
- 1차 실행에서 실험용 `forecast_goal` 이 남은 개월을 이번 달을 빼고 셌다 (4개월). 정답 기준(이번 달 포함 5개월)에 맞춰 고친 뒤 다시 돌렸고, 위 결과는 수정 후 실행이다.
