# 데모 데이터 점검: 3개월 내역으로 소비 쟁점을 도출할 수 있는가, 현실과 얼마나 먼가

- 관련: [08 데모 데이터 안내](../08-demo-data.md), [생성기 리포트](261126-1356-c-demo-transactions.md), [TODO demo-data](../todo/demo-data.md)

## 결론
- **현재 P1~P5 버전을 그대로 쓴다.** 3개월 내역만으로 심어 둔 쟁점의 신호가 다섯 명 모두 잡히고, 확정해야 할 질문 대상도 데이터에서 자연스럽게 드러난다.
- 다만 데이터가 현실보다 반복적이고 깨끗해서, 실제보다 도출이 쉽다. 아래 "다음 버전에 반영할 후보"는 데모 데이터를 새로 만들 때 검토한다.

## 배경
서비스는 3개월치 소비 내역으로 패턴을 파악하고, 고정 질의와 추가 질의를 거쳐 유저의 소비 쟁점을 도출한다. 그래서 두 가지를 점검했다.
1. 서비스가 실제로 받는 것(통합 내역 CSV + 고정 질의 답변)만으로 쟁점을 찾을 수 있는가
2. 현실 케이스와 너무 멀지 않은가

## 점검 방법
- 정답(`truth.json`)은 보지 않고 `onboarding/transactions.csv`만 읽는 임시 분석 스크립트를 돌렸다. 저장소에는 넣지 않았다.
- 페르소나에 맞춘 규칙은 쓰지 않았고, 어느 내역에나 쓸 수 있는 일반 규칙만 썼다.
  - 대분류별 월별 추이 (30% 이상, 2만 원 이상 변화)
  - 정기결제 후보: 같은 가맹점이 매달 비슷한 날에 결제됨. 같은 소분류의 중복, 금액 변동, 중간에 시작된 것도 본다
  - 요일·시간 집중: 금~일, 평일만, 22시 이후, 평일 점심시간
  - 앱 분류 의심: 쇼핑으로 분류됐는데 평일 점심시간에 반복
  - 이름 없는 입금·출금: 정기 여부, 정기 출금이 끊긴 달, 큰 결제 뒤 3일 안의 같은 금액 입금(1/n 정산 후보)
  - 환불, 할부, 카드대금, ATM, 쇼핑 날짜 집중(25일~3일)
- 생성 규칙의 기대 건수와 실제 건수, 요일 분포도 비교했다. 대부분 기대값 근처였고 요일 분포도 설정과 같았다.

## 결과 2: 함정이 함정 역할을 하는가
단순 분석은 의도한 대로 함정에 빠졌다. 그래서 평가용으로 쓸 수 있다.
- P4: "식비 증가"(218,200 → 380,200원)로 잡힌다. 실제로는 동아리 대표 결제 총액이고, 정산을 빼면 순지출이 작다.
- P5: "쇼핑 감소"(2,289,200 → 91,400원)로 잡힌다. 9월 노트북 할부 1,890,000원이 결제한 달에 전액 잡혔기 때문이다.
- P3: 10월 문화·여가가 562,900원으로 튄다. PT 할부 결제다.

## 결과 3: 노이즈가 만든 가짜 쟁점
- 의도하지 않은 추세도 나왔다: P1 쇼핑·교통 증가, P2 쇼핑 증가, P4 카페 감소.
- 무작위로 생긴 변동이라 현실에서도 흔하다. 다만 3개월(점 3개)로 본 추세는 근거가 약하다.
- 에이전트는 이런 추세를 쟁점으로 단정하지 말고, 목표와의 관련성과 크기로 우선순위를 정해야 한다. A에게 공유할 점이다.

## 결과 4: 현실과의 거리
**가까운 점**: 돈이 들고 나는 구조
- 급여일과 주말 처리, 카드대금 이체, 이름 없는 이체, 환불 행, 할부, 정산 입금, 앱 오분류, 늦게 들어오는 거래
- 생활 조건에서 나온 패턴: 직장인 평일 점심, 장거리 출퇴근 택시, 월급 직후 쇼핑 등. 성별·나이는 생성에 쓰지 않는다.

**먼 점**: 지출의 다양성과 불규칙성
- **가맹점이 너무 적다.** 3개월에 서로 다른 가맹점이 P1 23곳, P2 15곳, P3 16곳, P4 18곳, P5 17곳이고, 한 번만 간 곳은 0~2곳이다. 실제 내역은 한 번 가고 마는 식당·온라인몰이 길게 이어진다. 지금은 반복이 강해서 패턴을 찾기 쉽다.
- **일회성 큰 지출이 거의 없다.** 여행, 명절, 병원, 가전 같은 지출이다.
- **공휴일을 반영하지 않았다.** 한글날(10/9, 금)에도 P1·P3·P5에 출근 교통비와 점심이 찍히고, P3는 야근 택시까지 나온다.
- **자취·직장인의 관리비와 공과금(전기·가스·인터넷)이 없다.** P1·P4·P5가 해당된다.
- **금액이 범위 안에서 고르게 뽑힌다.** P1은 한 카페에서 40번 결제했는데 가격이 16가지다. 실제로는 메뉴 가격 몇 개에 몰린다.
- **같은 습관은 하루 최대 1회이고, 날마다 독립이다.** "배달한 날은 편의점에 안 간다" 같은 연관이 없다.
- **seed를 고른 페르소나가 있다.** P2·P4·P5는 스토리가 잘 보이는 표본을 골랐다. 신호가 의도대로 선명한 표본이다.
- **금액·빈도에 통계 근거가 없다.** 모두 데모 값이고 실제 연령대·직업별 통계와 비교하지 않았다 (미확인).
- **P2에 휴대폰 요금이 없다.** 부모님이 낸다고 가정했는데 고정 답변·숨은 사실에 적혀 있지 않다.

## 결과 5: 평가 기준에서 정할 점
정답의 월별 집계와 CSV로 계산한 값이 다르다.
- 예: P5 11월 쇼핑이 정답 237,600원, CSV 기준 91,400원이다.
- 원인 1: 10월 말 결제의 반품(32,800원, 113,400원)을, 정답은 원래 결제한 10월에서 빼고 CSV는 반품한 11월에 찍는다.
- 원인 2: 11/30 밤 거래는 온보딩이 아니라 12/1에 들어온다.
- 결제한 달 기준과 내역에 찍힌 달 기준 중 어느 쪽으로 채점할지 B와 정해야 한다.

## 다음 버전에 반영할 후보 (데모 데이터를 새로 만들 때 검토)
1. 일회성·다양성: 한 번만 가는 식당·온라인몰을 섞고, 3개월에 1~2건의 큰 일회성 지출(경조사, 병원, 명절 등)을 넣는다. 패턴 찾기 난이도에 가장 큰 영향을 준다.
2. 자취·직장인 관리비·공과금 추가 (P1·P4·P5)
3. 공휴일 반영(공식 달력으로 확인한 날짜), 가맹점별 메뉴 가격 목록
4. 정답 월별 집계를 두 기준(결제한 달 / 내역에 찍힌 달)으로 함께 제공
5. P2 휴대폰 요금을 부모님이 낸다는 숨은 사실 추가
6. 통계 비교: 공공 통계로 연령대별 소비 구성을 확인해 금액 보정 (조사 필요)
7. 이 리포트의 점검 스크립트를 테스트나 스크립트로 정식화할지

1~3을 넣으면 신호가 노이즈 속에 묻혀서 도출이 지금보다 어려워진다. 현실에는 그쪽이 더 가깝다. 넣을 때는 페르소나별 스토리 테스트(`tests/test_demo_data.py`)가 유지되는지 확인한다.
