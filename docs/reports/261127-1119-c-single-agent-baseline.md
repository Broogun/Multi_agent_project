# 싱글 에이전트 기준선과 비교 하네스를 따로 만든다 (초안)

- 날짜: 261127
- 작성: C (KIM-YUNHO), Claude Code로 작성
- 관련: [10 LLM 평가 계획](../10-llm-eval-plan.md) 단계 3~5, [1차 기준선 리포트](261126-2030-a-single-agent-p1-baseline.md), [아키텍처 명세 11.1](../architecture/goal_aware_consumption_agent_architecture.md), 코드 `src/spending_agent/baseline/`

## 결론
- 멀티 에이전트와 비교할 **싱글 에이전트 기준선(A1)과 비교 하네스**를 `src/spending_agent/baseline/`에 만들었다. 가짜 LLM으로 P1 62일(온보딩 + 피드백 10번)이 끝까지 돌고 채점된다.
- 하네스·도구·유저 시뮬레이터·채점은 에이전트 구조와 상관없이 공유한다. 멀티 에이전트는 `harness.Agent`(feedback, understand)만 구현하면 같은 조건으로 비교된다.
- **실제 OpenAI 실행은 아직 하지 않았다** (비용·키). 아래 숫자는 모두 가짜 LLM 결과다.

## 배경
1차 기준선(261126)은 연속 대화 구조였다. 기록마다 답하고, 대화 전체를 매번 다시 보냈으며, 주간·월간 피드백이 없었다. 10번 설계(기록은 조용히 이해하고, 말은 피드백 때만 한다)와 달라서 같은 세트로 멀티 에이전트와 비교할 수 없다.

## 한 일 / 결정
| 항목 | 결정 |
|---|---|
| 위치 | `baseline/` 별도 패키지. A의 서비스 코드 `agent/`(멀티 에이전트 뼈대)와 섞지 않는다 |
| 싱글 에이전트 | LLM 1개를 피드백(도구 사용, 유저에게 말함) / 유저 이해(도구 없음, 말 안 함) 두 방식으로 부른다 (10 §2). 호출 사이에는 요약 상태만 넘긴다 |
| 하루 진행 | 온보딩(D0 0시) → 21시까지 쓴 기록마다 유저 이해 → 21시에 그날 거래가 들어옴 → 피드백 날이면 피드백 → 21시 뒤 기록 |
| 세계 | ② 앱만(자기 기록 효과)으로 시작하고, 제안이 수락되면 ③ 앱 + 피드백(`responses.with_self`)으로 다시 만든다. 이미 들어온 거래·기록이 바뀌면 실패시킨다 |
| 도구 9개 | 지출 요약(요일별 포함), 거래 조회, 반복 결제(가격 변화·온보딩 뒤 첫 가맹점), 이름 없는 이체, 카드대금 맞춤, 목표 달성도(`goal_progress`), 목표 계산, 계산기, 질문. 보이는 거래만 본다 |
| 질문 | 피드백 중에 바로 답을 받는다(시뮬레이터). 피드백 한 번에 3개. 온보딩의 "추가 질의 → 쟁점" 순서를 지키려고 |
| 시뮬레이터 | 질문의 대상·문장에서 날짜·금액·낱말을 뽑아 숨은 사실과 맞춘다. 강한 키워드는 반응 규칙의 가맹점·대상 낱말이다. 하나로 정해지지 않으면 "잘 모르겠어요" |
| 거절 이유 | 에이전트에게 넘기지 않는다. 반응 규칙의 `why`에 숨은 사실이 들어 있어서다 |
| 숫자 검증 | `verify_response`. 허용하는 숫자는 이번 호출의 도구 결과, 유저가 준 숫자(고정 답변·기록·답), 에이전트가 고른 제안 강도(주 n회·금액)다. 걸리면 한 번 고쳐 내게 하고, 첫 답과 최종 답을 따로 남긴다 |
| 채점 | 규칙 채점: 쟁점 재현율, 숫자, 질문, 제안, 절약(피드백 효과 ③ − ②), 비용. 쟁점 매칭은 근거 거래ID → 유형 + 대상 → 대상 낱말 순서로 하고, 어느 방법으로 맞췄는지 남긴다. LLM 심판은 선택이며, 1차의 C06 오판을 막으려고 도구 결과를 같이 넘긴다 |

## 버린 대안
- 1차 스크립트(`scripts/eval_single_agent_p1.py`) 고치기: 구조가 10번 설계와 다르다. 1차 결과의 기록이기도 해서 그대로 둔다.
- `agent/` 안에 만들기: 비교 대상(멀티 에이전트 뼈대)과 비교 기준이 한 폴더에 섞인다.
- 질문을 피드백 출력에만 넣고 답은 다음 피드백 때 받기: 온보딩에서 답을 듣고 쟁점을 내는 흐름이 안 된다.
- LLM 시뮬레이터(1차 방식): 10 §6이 규칙형으로 정했다. 같은 질문에 같은 답이 나와야 반복 비교가 된다.
- 대화 전체 유지: 1차 기준선에서 토큰이 늘어난 원인이다 (호출당 입력 703 → 32,751).
