# 기준선 하네스를 P1~P5 반응 규칙에 맞춤 (제안 강도 4가지, 제안한 날, 기댓값 채점, 막은 쟁점)

- 날짜: 261127
- 작성: C (KIM-YUNHO)
- 관련: [반응 규칙 리포트](261127-1135-c-response-rules.md) "기준선 하네스와 맞출 것", [기준선 하네스 리포트](261127-1119-c-single-agent-baseline.md), [10 LLM 평가 계획 §5~§7](../10-llm-eval-plan.md)

## 결론
- 기준선 하네스(`src/spending_agent/baseline/`)를 P1~P5 반응 규칙과 맞췄다. 바꾸기·목표 조정 제안이 이제 수락될 수 있다. 기간이 붙은 거절도 걸린다.
- 채점은 에이전트가 실제로 본 세계로 한다. 절약 점수는 기댓값을 쓴다.
- 데이터와 반응 규칙은 바꾸지 않았다. 싱글 에이전트에서는 프롬프트의 강도 설명만 바꿨다.

## 배경
- 하네스는 반응 규칙이 P1에만 있던 시점에 만들었다. 그래서 P1~P5 규칙과 맞지 않는 곳이 네 군데 있었다.
  1. 제안 강도를 `per_week`·`amount`만 넘겼다. 그래서 `to`(바꾸기)·`deadline`(목표 조정)이 필요한 제안은 내용이 맞아도 수락되지 않았다.
     - 바꾸기: P2 테이크아웃, P3 요금제, P4 회식비 미리 걷기, P5 장바구니 보류
     - 목표 조정: P4, P5
  2. 반응 판정에 제안한 날을 넘기지 않았다. 그래서 기간이 붙은 거절이 걸리지 않았다 (P2 시험기간 카페 줄이기, P4 잔액 바닥 기간 노트북 저축). 나쁜 제안이 수락돼 점수가 부풀었다.
  3. 절약 점수가 실제 거래 값이라, 결제 한 건이 큰 습관(P5 쇼핑)에서 운에 흔들렸다.
  4. 쟁점 정답을 서비스 없는 세계(①)로 만들었다. 그래서 제안으로 막은 쟁점도 '놓쳤다'로 감점됐다 (P2 게임 상한).

## 한 일 / 결정
- **제안 강도** (`simulator.strengths`)
  - `responses.STRENGTHS` 4가지를 모두 넘긴다. 형식이 틀린 값은 없는 것으로 본다. 그러면 대개 수락되지 않는다.
    - `per_week`·`amount`: 숫자
    - `deadline`: YYYY-MM-DD
    - `to`: 글자
  - 수락 기록(`accepted`)에도 4가지를 남긴다. 세계를 다시 만들 때 목표 조정의 새 마감일과 금액이 반영된다.
  - 숫자 검증: 에이전트가 고른 새 마감일은 사실이 아니라 선택이므로 허용한다. 주 n회·금액과 같은 처리다.
- **제안한 날**: 피드백 날짜를 `responses.react`에 넘긴다.
- **채점 세계** (`harness.served_world`, `score.py`)
  - 정답은 하네스가 에이전트에게 보여 준 세계와 같은 것으로 만든다. 수락이 있으면 ③, 없으면 ②다.
  - 막은 쟁점(`prevented`)은 필수에서 빼고 선택으로 본다. 짚으면 선택 쟁점을 맞힌 것으로 센다.
  - 판단 기준: 근거 거래가 하나라도 생기지 않았으면 막은 것으로 본다. P2 게임 상한은 12월 말 초과 결제 3건 중 2건이 생기지 않는다. 남은 1건은 상한 안의 결제라 '상한 초과'라는 쟁점 자체가 없어진다.
  - 결과에 `issues.prevented`(전체)와 시점별 `prevented`를 남긴다.
- **절약 점수**
  - 기본 점수를 `expected_feedback_effect`로 바꿨다.
  - 실제 거래 값(`feedback_effect`), 자기 기록 효과 기댓값, 바뀐 필요액(`served_required_by_now`)은 함께 남긴다.
  - CLI 요약도 기댓값을 먼저 보여 준다.
- **싱글 에이전트 프롬프트**: 행동별로 적을 강도 칸을 적었다. 줄이기 `per_week`, 저축 늘리기·상한 정하기 `amount`, 바꾸기 `to`, 목표 조정 `deadline`(+ `amount`). 나머지 칸은 뺀다.

## 버린 대안
- **일부만 막힌 쟁점은 필수로 두기**: P2 게임 상한처럼 근거가 하나 남아도 쟁점이 없어지는 경우가 있다. 필수로 두면 제안을 잘 한 에이전트가 감점된다.
  - '선택'으로 두면 놓쳐도 감점이 없고, 짚으면 선택 쟁점을 맞힌 것으로 센다. 그래서 선택으로 정했다.
- **형식이 틀린 강도를 고쳐서 넘기기**(예: "3만" → 30000): LLM 출력 형식을 지키는지도 평가 대상이다. 고쳐 주면 형식을 지키는 모델과 안 지키는 모델의 차이가 사라진다.
