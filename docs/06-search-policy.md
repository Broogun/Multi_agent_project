# 06. 검색 사용 원칙

검색 기능을 만들거나 고치는 사람·에이전트는 이 문서를 지킨다. 아래 내용은 프로젝트의 데이터 처리 원칙이며 특정 제공자의 약관 해석이 아니다.

## 현재 상태

검색·LLM 제공자는 미정이며 실제 외부 API 연동은 보류한다. 화면과 연동은 `fakes.fake_search_panel` 및 기존 `SearchPanelEvent` 계약으로 개발한다. 제공자를 정하면 구현 전과 발표 전에 공식 약관·표시 규칙·지원 지역·가격을 확인하고 검토 결과를 리포트로 남긴다.

## 반드시 지킬 것

| 규칙 | 프로젝트 원칙 | 구현 |
|---|---|---|
| 검색 결과를 **별도 검색 창**에 표시한다 | 에이전트 답변과 구분 | 제공자의 검색 제안이 있으면 `suggestions_html` 로 함께 전달 |
| 결과를 **수정하지 않고**, 에이전트 답변 등 다른 내용을 **끼워 넣지 않는다** | 원문 그대로 표시 | 답변 텍스트·링크·제목을 손대지 않는다 |
| 결과를 **에이전트 대화·state·DB에 넣지 않는다** | 저장·분석·학습 입력 금지 | 검색 결과는 UI 이벤트로만. 테스트로 확인 |
| 링크로 **크롤링·색인·DB를 만들지 않는다**. 링크된 페이지를 코드나 에이전트가 열지 않는다 | 사용자 직접 확인 | 링크는 사용자가 누르는 용도로만 |
| 링크에 **중간 페이지·리다이렉트·클릭 추적**을 추가하지 않는다 | 원래 링크 유지 | 제공자가 준 URL로 바로 연다 |
| **검색어에 개인정보·재무 정보를 넣지 않는다** | 상품명·용량만 전달 | 검색어 제한과 개인정보 필터 검증 |

## 가격과 계산

- 검색 결과에 보이는 가격으로 절감액을 계산하지 않는다. LLM이 만든 숫자이고, 오래되었거나 틀릴 수 있다.
- LLM을 사용하는 검색 제공자를 도입하면 구체 가격을 단정하지 않고 판매처 확인을 안내하도록 요청한다.
- 계산에 쓰는 가격의 출처 유형: `user_verified`(사용자 확인), `receipt_ocr`, `capture_ocr`, `public_api`. 검색 결과는 입력 경로가 없다.
- 사용자가 확인한 가격은 그 사용자 본인의 비교에만 쓴다. 여러 사용자 가격 공유는 향후 확장 (비식별화·동의·검증 필요).
- 검색 창 고지 문구: "검색 결과이며, 실제 가격은 판매처에서 확인하세요."

## 비용

제공자 미정으로 과금 방식·금액은 미확인이다. 도입 전에 공식 가격과 호출 제한을 확인하고 예산을 정한다. 현재 가짜 구현과 테스트는 외부 검색 API를 호출하지 않는다.
